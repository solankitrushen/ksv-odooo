# Project OSMO Client — Structure & Click Flows

> Full structure, routing, and click-flow reference for the React/Vite frontend. Use this when migrating to Next.js or onboarding.

---

## 1. Project Overview

**Project OSMO** is a marketing SaaS admin frontend: social, SEO, ads, and outreach tools under one app. The client is a **React 18+ SPA** with Vite, React Router v7, Tailwind v4, Shadcn/UI, and React Query.

## 4. Provider Tree (Dependency Order)

Providers are composed via `descriptors.jsx` and `compose.js` (topological sort). **Order must not change** in `main.jsx`.

```
QueryProvider (React Query)
  └─ ToastProvider (deps: query)
      └─ TooltipProvider (deps: toast)
          └─ AuthProvider (deps: tooltip)
              └─ RouterProvider (deps: auth)
                  └─ <App /> → <Suspense><Outlet /></Suspense>
```

- **SidebarProvider** is not in the root tree; it wraps layout inside `AppLayout` when a page uses `<AppLayout>`.

## 6. Guards Behavior

- **RequireGuest**: If authenticated → redirect to `/dashboard`. Used on `/auth/*`.
- **RequireAuth**:
  - Not authenticated → redirect to `/auth/login` (state: `{ from: location }`).
  - Authenticated but `!user.isOnboarded` and `requireOnboarding !== false` → redirect to `/onboarding`.
  - **Exception**: `/onboarding` uses `requireOnboarding={false}` so users can complete onboarding.

## 7. Click Flows (Where Clicks Go)

### 7.1 Entry points

| Entry | Target |
|-------|--------|
| Open `/` | Redirect → `/dashboard` |
| Open `/auth/login` | Login page (if guest) |
| Open `/auth/signup` | Signup page (if guest) |
| Open any protected path while logged out | RequireAuth → `/auth/login` |
| Open any `/auth/*` while logged in | RequireGuest → `/dashboard` |

### 7.2 Auth flow (sequential)

```
Landing (/) → redirect /dashboard
  → if not authenticated: RequireAuth → /auth/login

/auth/login
  ├─ "Sign in" (submit) → login() → navigate("/dashboard")
  └─ "Sign up" link → /auth/signup

/auth/signup
  ├─ "Create account" (submit) → signup() → navigate("/auth/login")
  └─ "Sign in" link → /auth/login

/auth/forgot
  ├─ After submit (sent) → "Back to login" → /auth/login
  └─ (no other links in snippet)

/auth/2fa
  └─ (on success would go to /dashboard; implementation may vary)
```

### 7.3 Onboarding flow

```
User authenticated but !isOnboarded → RequireAuth → /onboarding

/onboarding
  ├─ Complete onboarding → navigate("/dashboard") or navigate("/onboarding/setup", { state: { website } })
  └─ support link → mailto:support@osmo.ai

/onboarding/setup
  └─ Finish → navigate("/settings/integrations", { replace: true })
```

### 7.5 In-page links (by feature)

**404**

- "Go home" → `/` (then redirect to `/dashboard`).

**Social**

- **Events**: "Create event" → `/social/events/create`; event row → `/social/events/:eventId`; edit → `/social/events/:eventId/edit`; back → `/social/events`.
- **CreateEvent**: After create → `/social/events/:eventId`; back → `navigate(-1)`.
- **Analytics**: "Connect Platforms" → `/social/integrations`; "Create Post" → `/social/composer`.

**SEO**

- **Generator**: After generate → `/seo/editor/:id`.
- **Blogs**: Row click → `/seo/editor/:id`; "New blog" → `/seo/generator`.
- **Keywords**: Actions → `/seo/generator?…` (query params).
- **Preview**: Back → `navigate(-1)`; "Edit" → `/seo/editor/:id`; "Blogs" → `/seo/blogs`.

**Outreach**

- **Composer**: "Email Integrations" → `/outreach/email/integrations`.
- **Campaigns**: "Email Integrations" → `/outreach/email/integrations`; "Templates" → `/outreach/templates`; "Import" → `/outreach/import`.
- **BusinessCard**: Shareable link → external `href` (same app: `/business-card/:shareableId`).

**Settings**

- **Integrations**: Social CTA → `/social/integrations`; Outreach CTA → `/outreach/email/integrations`.

**On Your Desk**

- Item click → `viewPath` (e.g. `navigate(viewPath)`); social event → `/social/events/:id`; SEO blog → `/seo/blogs/:id` (or editor as per implementation). Some items use `item.data.context.targetUrl` as external `href`.

**PostOnboardingSetup**

- OAuth / external links use `href={url}` (no in-app route).

## 9. API Layer (for migration)

- **Base**: `services/api/client.js` — Axios instance, `withCredentials: true`, base URL from env (`VITE_BACKEND_*_PORT`).
- **Interceptors**: Attach `Authorization: Bearer <cookie>`; on 401 redirect to `/auth/login`.
- **Modules**: `auth.api.js`, `seo.api.js`, `social.api.js`, `events.api.js`, `on-your-desk.api.js`, `campaign.api.js`, `outreach.api.js`, etc. All under `services/api/`.

---

## 10. Contexts & Hooks (key for state)

- **Auth**: `AuthContext` / `AuthProvider` → `useAuth()` (user, isAuthenticated, isLoading, login, logout, refreshUser).
- **Router**: `RouterContext` / `RouterProvider` → `useRouter()` (push, navigate, router).
- **Sidebar**: `SidebarContext` / `SidebarProvider` (in AppLayout) → `useSidebar()` (expandedSection, toggleExpanded).
- **Toast**: `ToastProvider` → `useToast()`.
- **Query**: React Query `QueryClient` / `QueryProvider` → `useQuery`, `useMutation` in hooks.

## 11. Index page (dev directory)

`ui/pages/Index.jsx` is a **directory of all pages** (sections: Auth, Core, Social, SEO, Ads, Outreach, Admin, Settings). It is **not** mounted at `/` in production; the router redirects `/` → `/dashboard`. If you need a true landing or dev sitemap in Next.js, you can recreate this page and route separately.
